# Анализ задачи

## Что строим
Локальное open source приложение (Rust, Windows в первую очередь), которое в реальном времени:
1. слушает выбранные пользователем источники звука (микрофон, весь системный звук, конкретное приложение);
2. распознаёт речь (ASR);
3. переводит её на выбранный язык (MT);
4. отдаёт результат в три вида вывода: поток текста (OBS и интеграции), браузерный оверлей с
   настраиваемым внешним видом, лог с временем в часовом поясе пользователя.

## Зафиксированные решения
| Вопрос | Решение |
|---|---|
| Язык | **Rust** — ради предсказуемой задержки и минимальных ресурсов (см. [STACK.md](STACK.md#почему-rust)) |
| ОС | **Windows 10 (2004+) / 11** в первую очередь; Linux и macOS — после v1.0 |
| Источники | микрофон и системный звук; пользователь сам выбирает, что слушать, вплоть до отдельного приложения; несколько источников одновременно |
| Языки | любые ↔ любые, пара задаётся для каждого источника |
| Железо | обязательно работает на CPU; GPU (NVIDIA — CUDA, AMD/Intel — Vulkan) ускоряет |
| Лицензии моделей | только модели, разрешающие коммерческое использование ([политика](PLUGINS.md#лицензионная-политика-моделей)) |
| Расширяемость | модели и форматы — плагины в трёх гнёздах конвейера: Recognizer, Translator, Output ([PLUGINS.md](PLUGINS.md)) |

## Главные риски и как их снимаем

| Риск | Почему опасно | Мера |
|---|---|---|
| **Задержка и «прыгающий» текст** | Whisper не потоковый: частичные гипотезы постоянно меняются | LocalAgreement-2, стабильная часть и хвост показываются раздельно, переводятся только финальные сегменты |
| **Галлюцинации Whisper на тишине и шуме** | фантомные фразы появляются в эфире | VAD-гейт, порог `no_speech_prob`, фильтр повторов, стоп-лист фраз |
| **Нагрузка во время игры и стрима** | нарушает правило 4 | Rust без GC, MMCSS для аудио, пониженный приоритет инференса, простой при тишине, профили моделей, бенчмарк в CI |
| **Сборка C++-движков из Rust** | `whisper-rs` и `ct2rs` требуют CMake, clang, CUDA и Vulkan SDK; `ct2rs` — community-обёртка | проверка в фазе 0; каждый движок — отдельный плагин-крейт; запасной путь для перевода — ONNX через `ort`; в релизах всё уже собрано |
| **Захват отдельного приложения** | Process Loopback API — COM и асинхронная активация | крейт `windows`, отдельный модуль в `audio-win`, проверка на Win10 22H2 и Win11 в фазе 0 |
| **Лицензии моделей** | лучшие модели «любой↔любой» (NLLB, Seamless) — NC, а аудитория монетизирует контент | в каталоге только Opus-MT (CC-BY), M2M100 (MIT), MADLAD-400 (Apache-2.0); тест проверяет allowlist |
| **Качество перевода коротких фрагментов** | MT без контекста ошибается | перевод целыми предложениями, контекст предыдущих сегментов, опция LLM |
| **Безопасность локального сервера** | любой сайт в браузере может обращаться к localhost | Host/Origin-проверки, токены, только 127.0.0.1 (см. SECURITY.md) |

## Открытые вопросы (не блокируют старт)
1. **Название проекта** — решено: `voice-to-text`, репозиторий https://github.com/noNhead/voice-to-text.
2. **Лицензия** — Apache-2.0 или `MIT OR Apache-2.0` (рекомендация: `MIT OR Apache-2.0`, стандарт Rust).
3. **Язык документации для сообщества** — сейчас русский; README стоит продублировать на английском перед публикацией.
4. **Окно субтитров поверх экрана** для звонков — в бэклоге после v1.0.
5. **TTS-озвучка перевода** — вне рамок v1; архитектура это позволяет (TTS — ещё один output-плагин).

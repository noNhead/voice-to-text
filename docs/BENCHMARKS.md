# Замеры

Результаты замеров фазы 0. Каждый замер можно повторить командой из раздела. Цифры — для конкретной
машины; бюджеты — в [STACK.md](STACK.md#бюджет-ресурсов-цели-проверяются-бенчмарком-в-ci).

## Захват звука (WASAPI) — 2026-11-16

**Машина:** AMD Ryzen 7 5800H (8 ядер / 16 потоков), Windows 10 22H2 (сборка 19045).
Ввод — Focusrite USB Audio, вывод — Bluetooth-наушники. Сборка `--release`.

```bash
cargo run -p vtt-audio-win --release --example probe -- capture mic --seconds 30
```
```bash
cargo run -p vtt-audio-win --release --example probe -- capture app:chrome --seconds 30
```

| Источник | Длительность | Потеряно сэмплов | Разрывы | Пакет | CPU (весь процесс probe) | RAM (рабочий набор) |
|---|---|---|---|---|---|---|
| Микрофон (устройство по умолчанию) | 30 с | 0 | 1 (первый пакет) | 10 мс | 6.6 Мтактов/с ≈ **0.21 %** одного ядра | 9.1 МБ |
| Loopback вывода по умолчанию | 10 с | 0 | 1 (первый пакет) | 10 мс | — | 9.1 МБ |
| Process Loopback: `chrome.exe` с дочерними процессами | 30 с | 0 | 0 | 10 мс | 11.5 Мтактов/с ≈ **0.36 %** одного ядра | 9.7 МБ (пик 10.5) |
| Loopback беззвучного устройства (Realtek) | 5 с | 0 | 1 | 10.7 мс | — | 9.3 МБ |
| Process Loopback беззвучного приложения (`steam.exe`) | 5 с | 0 | 0 | 10 мс | — | 9.3 МБ |

Выводы:
- **Process Loopback работает на Windows 10 22H2** (19045). Захват звука отдельного приложения подтверждён.
- Поток захвата регистрируется в MMCSS «Audio».
- CPU в таблице включает и сам probe (подсчёт RMS, запись в консоль), поэтому захват дешевле
  0.3 % одного ядра, а это ≈ 0.02 % машины. Бюджет «< 0.5 % CPU в простое» выполняется с большим запасом.
- `GetProcessTimes` на такой нагрузке показывает 0: его шаг ~15.6 мс. Поэтому замеры CPU делаются
  через `QueryProcessCycleTime` (такты); пересчёт в долю ядра — по номинальной частоте (`VTT_CPU_GHZ`, по умолчанию 3.2).
- Число сэмплов на 0.1–0.2 % меньше ожидаемого по часам: это задержка старта (~20 мс) и последний пакет,
  который остаётся в буфере на момент остановки. Это не потери.
- На этой сборке Windows loopback присылает пакеты (с флагом silent) и при полной тишине. Поэтому заполнение
  пауз тишиной (`gap.rs`) не понадобилось, но оно остаётся страховкой: по документации WASAPI loopback
  может перестать присылать пакеты, когда ничего не воспроизводится.

**Ещё не проверено:** Windows 11; захват под нагрузкой (игра + запись OBS); переключение и отключение устройства
во время захвата; долгий (часы) прогон на дрейф часов.

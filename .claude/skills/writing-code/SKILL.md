# Написание кода в voice-to-text (Rust)

Цель проекта — **оптимизированное** приложение, которое работает рядом с игрой, OBS и звонком. «Работает» — недостаточно:
каждое решение оценивается по задержке, CPU, RAM и потерям аудио. Перед работой сверься с `docs/ARCHITECTURE.md`
и `docs/STACK.md`. Если задача требует отойти от них — остановись и спроси.

## 1. Четыре правила проекта — фильтр для каждого решения
1. **Бесплатно и open source.** Зависимость — только с лицензией из allowlist `deny.toml` (MIT, Apache-2.0, BSD,
   ISC, Zlib, Unicode, MPL-2.0…). **Модели — только с коммерческой лицензией** (политика в `docs/PLUGINS.md`).
   NC, research-only, Llama/Gemma-подобные лицензии в `ModelSpec` встроенных плагинов не добавлять. Лицензию
   проверять по карточке конкретной модели и заполнять `attribution`.
2. **Локально.** Никаких сетевых вызовов, кроме скачивания моделей через ModelManager и loopback-подключений
   (OBS, локальная LLM). Никакой телеметрии и автопроверки обновлений.
3. **Качество.** Изменение распознавания или перевода → прогон golden-тестов (`cargo test -p … --features golden -- --ignored`).
4. **Ресурсы.** Изменение горячего пути (audio → dsp → asr → mt) → `cargo bench` до и после. Регрессия больше 5 % — обоснование в PR.

Запрещено без обсуждения: Electron, Tauri/WebView в фоне, PyTorch/libtorch, облачные SDK, загрузка DLL-плагинов,
новые C/C++-зависимости вне плагинов-движков.

## 2. Стиль Rust
- Edition 2024, MSRV = текущий stable из `rust-toolchain.toml`. `cargo fmt` (max_width 100), clippy `-D warnings` с
  `clippy::pedantic` (точечные `#[allow]` — с комментарием-причиной).
- `#![forbid(unsafe_code)]` во всех крейтах, кроме `audio-win` и плагинов-движков с FFI. Там `unsafe` живёт
  только в маленьких обёртках, и каждый блок снабжён комментарием `// SAFETY:` с инвариантами.
- Ошибки: `thiserror` в библиотеках (свой `enum Error` на крейт), `anyhow` только в `app`. Никаких `unwrap()`/`expect()`
  вне тестов и доказуемо невозможных случаев (тогда `expect("причина")`). Паники не используются для управления потоком.
- Значения и события — неизменяемые структуры; `#[non_exhaustive]` на публичных enum/struct в `plugin-api`.
- Нет глобального изменяемого состояния (`static mut`, `lazy_static` с `Mutex`). Зависимости передаются явно, сборка — в `app`.
- Логи: `tracing`. **Распознанный и переведённый текст никогда не логируется на уровне `info` и выше**: это личные
  данные. Только `trace`, и только при включённом пользователем debug-режиме. Секреты — тип-обёртка без `Debug`.
- Время: `jiff::Timestamp`/`Zoned` с таймзоной пользователя; длительности — `std::time::Instant`. Часы передаются через
  трейт `Clock`, чтобы подменять их в тестах.
- Пути: базовые папки только из одного модуля (`directories`); пользовательские имена валидируются (см. скилл `security`).

## 3. Производительность и горячий путь
- **Аудиопоток** (WASAPI): только `rtrb::Producer::write_chunk_uninit`/`push`. Нельзя: аллокации (`Vec::new`, `Box`,
  `format!`, `String`), `Mutex`, логирование, I/O, вызовы моделей. Поток регистрируется в MMCSS («Audio»).
- **dsp-поток**: буферы выделяются один раз при старте (`Vec::with_capacity`, затем `clear()`/`extend_from_slice`).
  Ресемплинг делает WASAPI (запрашиваем f32 моно 16 кГц); `rubato` — только для платформ без такой возможности,
  с заранее выделенными выходными буферами. Никаких `collect()` в цикле на каждый блок.
- **Замеры CPU** малых нагрузок — через такты (`ProcessUsage::cpu_cycles`, `QueryProcessCycleTime`), а не
  `GetProcessTimes` (шаг ~15.6 мс). Результаты фазы 0 и команды для повторения — в `docs/BENCHMARKS.md`.
- **Инференс** — в выделенных `std::thread` (`asr-*`, `mt-*`) с пониженным приоритетом, а не в tokio и не в `rayon`
  по умолчанию. Потоки движка — строго `ctx.cpu_threads()`.
- Между стадиями — **ограниченные** каналы (`crossbeam-channel::bounded`, `tokio::sync::mpsc`). При переполнении
  выбрасывается `partial`, `final` — никогда. Каждый сброс увеличивает счётчик-метрику.
- Окно аудио в другой поток передаётся как `Arc<[f32]>` или из пула буферов, без лишних копий.
- tokio: `current_thread` или максимум 2 воркера. Блокирующее — через `spawn_blocking`. Никаких `block_on` внутри async.
- Модели загружаются лениво и выгружаются после простоя; одна копия модели на процесс (`Arc`).
- Профиль `release`: `lto = "fat"`, `codegen-units = 1`, `opt-level = 3`, `panic = "abort"` только в бинарнике
  (в потоках плагинов нужен `catch_unwind`, поэтому для отдельных крейтов это проверяется отдельно).
- Любая «оптимизация» подтверждается `criterion`-бенчмарком или замером, иначе выбираем более простой код.

## 4. Плагины и ядро
Полные контракты — в `docs/PLUGINS.md`. Сначала определи, где живёт задача:

| Если задача про… | Это… |
|---|---|
| конкретную модель/движок распознавания или перевода, конкретный формат вывода | **плагин** (`plugins/<kind>-<id>/`) |
| звук, ресемплинг, VAD, сегментацию, стабилизацию, фильтр галлюцинаций, пивот, батчинг, очереди, модели, сервер, IPC | **ядро** (`crates/*`) |

Если логика нужна двум и более плагинам одного гнезда — она принадлежит ядру.

Правила:
- Плагин зависит **только** от `vtt-plugin-api` (и своих внешних библиотек). Зависимость плагина от `core`, `host`,
  `server` или другого плагина — ошибка (проверяется CI-скриптом по `cargo metadata`).
- Recognizer/Translator: синхронные методы, без своих потоков, кроме потоков движка в пределах `cpu_threads`;
  не открывают аудиоустройства, не делают VAD, не скачивают модели — путь к модели только через `ctx.model_path()`.
- Output: async, блокирующий I/O через `spawn_blocking`, веб-части — только через `WebMount`.
- Манифест заполнен честно: `license` (SPDX), `network`, `devices`, требования моделей к RAM/VRAM.
- Новый плагин = крейт + манифест + контрактные тесты (`vtt_plugin_api::testing`) + golden-тест для моделей +
  feature-флаг в `app` + строка в таблице встроенных плагинов в `docs/PLUGINS.md`.
- `core` не зависит от ОС и плагинов. ОС-код — только в `audio-win` (и будущих `audio-*`) под `cfg(windows)`.
- Ядро изолирует сбои: `catch_unwind` на границе потоков плагинов, таймауты, перезапуск с backoff.

Публичные контракты (не ломать без смены мажорной версии `PLUGIN_API_VERSION`): трейты и типы `vtt-plugin-api`,
IPC-протокол внешних плагинов, JSON-схема событий (`segment`/`status`/`clear`, изменения только аддитивные).

## 5. Конфиг
- Схема — `serde`-структуры в `app::config` с `#[serde(deny_unknown_fields)]`, значениями по умолчанию и
  `schemars`-описаниями (из них строится UI).
- Меняешь схему — увеличь `schema_version` и добавь миграцию с тестом.
- Секреты не хранятся в TOML — только в Windows Credential Manager (`keyring`).

## 6. Web (оверлей и UI)
- `overlay`: ванильный JS (ES2022), без фреймворков и CDN; файлы встраиваются в `.exe` (`rust-embed`).
  Текст — только через `textContent`/`createTextNode`, **никогда** через `innerHTML`. Внешний вид — CSS-переменные темы.
  Анимации — `transform`/`opacity`. Переподключение к WS с экспоненциальной задержкой; неизвестные поля события игнорируются.
- `web/settings`: Svelte 5 + TypeScript strict; формы по JSON Schema; admin-токен в `sessionStorage`, только в
  заголовке `Authorization`.

## 7. FFI и Windows API
- WinAPI — только через крейт `windows` (официальный). COM-объекты — в RAII-обёртках; `CoInitializeEx` на поток явно.
- Все `HRESULT` проверяются и превращаются в ошибки крейта с контекстом (какой вызов, какое устройство).
- C++-движки (whisper.cpp, CTranslate2): никаких сырых указателей наружу из крейта-плагина; время жизни модели и
  контекста привязано к Rust-типу; панику через границу FFI не пропускаем.

## 8. Тесты
- Unit-тесты рядом с кодом (`#[cfg(test)] mod tests`); интеграционные — в `tests/` крейта.
- Unit-тесты не загружают реальные модели и устройства: фейковые VAD/recognizer/translator через трейты.
- Golden-тесты (реальные модели, `tests/data/*.wav` + эталонные тексты): `#[ignore]` + feature `golden`, порог WER/BLEU.
- Бенчмарки: `criterion` для DSP/VAD/стабилизатора; отдельный бенчмарк-бинарник для полного конвейера (CPU, RAM, задержка, потери).
- Каждый исправленный баг — регрессионный тест.
